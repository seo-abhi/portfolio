AllCloneScript SEO Case Study

Building a Separate Search Identity for a Marketplace With an Overlapping Product Catalog

When I started working on AllCloneScript in June 2024, it was a relatively new digital-product marketplace launched after Bitrix Theme.

The unusual part of the project was that almost all of its products were also available on Bitrix Theme, another marketplace I was managing at the same time.

The downloadable products themselves were largely the same: Figma and UI design files, HTML and web templates, WordPress themes, Flutter products, and complete scripts.

From an SEO perspective, this created a difficult problem. If both websites used the same keywords, product names, titles, descriptions, blogs, and internal links, they would gradually become search-engine copies of each other.

I needed to build a separate keyword strategy, content strategy, page positioning, internal-linking system, technical foundation, and search identity for AllCloneScript while continuing to manage Bitrix Theme simultaneously.

I managed AllCloneScript from June 2024 to November 2025 as its main SEO owner.

The Starting Point

AllCloneScript was a new marketplace, but its biggest SEO challenge did not come from its age. It came from its relationship with Bitrix Theme. Almost the entire product catalogue overlapped. That meant two separate domains could potentially contain:

  • The same downloadable Figma file
  • The same HTML template
  • The same WordPress theme
  • The same Flutter product
  • The same complete script

If both domains targeted the same search terms in the same way, they could begin competing against each other unnecessarily. At the same time, AllCloneScript itself had the usual problems of a new digital-product marketplace:

  • Thin product content
  • Weak metadata
  • Weak internal linking
  • Indexing problems
  • Missing structured data
  • Sitemap issues
  • Basic robots.txt
  • Filter and pagination URLs
  • Page-speed problems
  • Almost no backlink profile
  • No blog strategy

The challenge therefore was not simply: How do I make AllCloneScript rank? It was: How do I make AllCloneScript rank without turning it into a second Bitrix Theme?

The Initial SEO Problems

The project combined normal marketplace SEO problems with a much more unusual cross-domain challenge.

Cross-Domain SEO

The biggest strategic risks included:

  • Same products across two domains
  • Similar search intent
  • Potentially similar product names
  • Overlapping commercial keywords
  • Similar blog opportunities
  • Similar category themes
  • Two websites competing for the same queries

This required page-level differentiation from the beginning.

On-Page SEO

Common page-level issues included:

  • Thin product descriptions
  • Weak keyword targeting
  • Poor metadata
  • Limited content depth
  • Weak page differentiation
  • Internal keyword cannibalization
  • Cross-domain keyword competition
  • Similar products with similar intent

The product pages needed both normal optimization and a separate identity from their Bitrix equivalents.

Technical SEO

Technical issues included:

  • Sitemap containing unnecessary URLs
  • Basic robots.txt configuration
  • Filter URLs
  • Parameter URLs
  • Pagination
  • Duplicate URLs
  • Missing canonicals
  • Crawled, currently not indexed pages
  • Discovered, currently not indexed pages
  • Weak internal linking
  • Slow page speed
  • Missing schema
  • Image optimization problems

One notable difference from Bitrix Theme was that AllCloneScript did not have the same large tag-page problem because it did not use that tag architecture.

Content

AllCloneScript effectively started with:

0 Blogs

That created both a problem and an opportunity. There was no existing content library to repair. But it also meant I could build a separate informational identity from the beginning instead of inheriting a blog strategy that duplicated Bitrix Theme.

Off-Page SEO

The backlink profile was also very weak. However, AllCloneScript did not receive the same level of off-page investment as Bitrix Theme. The authority strategy therefore remained lighter and focused mainly on initial external signals.

Starting With Cross-Domain Differentiation

The first major strategic decision was treating AllCloneScript as a separate search property. I did not want it to become: Bitrix Theme With a Different Checkout Method The SEO needed a distinct reason to exist. That meant separating the two websites through:

  • Keyword selection
  • Product naming
  • Metadata
  • Product descriptions
  • Blog strategy
  • Landing-page focus
  • Internal-linking emphasis
  • Search positioning

This became the foundation for almost every later SEO decision.

Managing Cross-Domain Keyword Competition

There were still situations where both websites could naturally appear around the same broader searches. Examples included:

  • meme coin website template
  • crypto website template
  • betting website template
  • meme coin Figma UI kit

I did not treat every shared search theme as automatically harmful. If both pages had a legitimate reason to exist and different enough targeting, overlap could happen naturally. Where direct competition needed to be reduced, I differentiated the pages using:

  • Different primary keywords
  • Different secondary keywords
  • Different titles
  • Different descriptions
  • Different anchor text
  • Different long-tail terms
  • Different content angles

The objective was not: Never let both domains rank for the same topic It was: Do not make both domains target the same topic in exactly the same way.

Rebuilding Product SEO From Scratch

Most AllCloneScript product pages initially had thin content. Even though many products were identical to products already listed on Bitrix Theme, I did not copy the optimized Bitrix content across. Each AllCloneScript product needed to be treated as a separate SEO landing page. My product SEO work included:

  • Product titles
  • Meta titles
  • Meta descriptions
  • H1s
  • Product descriptions
  • Keyword placement
  • URLs
  • Image alt text
  • Internal links
  • Structured data
  • Content expansion

This required more manual work, but it reduced the risk of making both websites look identical from a search perspective.

Cleaning the XML Sitemap

The initial sitemap included many URLs that did not need to be prioritized for organic search. I reviewed the URL types and focused the sitemap more clearly around valuable pages. The important page groups included:

  • Products
  • Clone-script pages
  • Categories
  • Services
  • Blogs
  • Other key commercial pages

A sitemap does not guarantee indexing. So the cleanup was combined with: Better Content + Stronger Internal Linking + Cleaner Crawl Paths + Duplicate Handling + Clear Page Targeting During the project, I observed more consistent discovery and indexing of important commercial URLs.

Managing Filters, Parameters and Pagination

Filter and pagination URLs were creating unnecessary crawl paths. Where those utility URLs did not provide independent search value, I worked with developers to restrict unnecessary crawling. For low-value or duplicate URLs that remained crawlable, I used the appropriate:

  • Canonical
  • noindex
  • Crawl-control strategy

depending on the situation. This distinction mattered because:

Crawl Control Is Not the Same as Index Control

The objective was to help search engines focus on: Products + Clone-Script Pages + Categories + Services + Blogs instead of unnecessary URL combinations.

Solving Product Indexing Problems

  • Internal linking

I also cleaned the surrounding technical signals. Over time, I observed more important products entering search properly.

Improving Canonicalization and Duplicate URL Handling

Duplicate and similar URLs also required clearer handling. Depending on the URL type, I used:

  • Preferred canonical URLs
  • Content differentiation
  • noindex
  • Crawl restrictions for low-value utility paths

The objective was not simply: Reduce URL Count It was: Make Every Indexable Page Have a Clear Reason to Exist That principle applied to both technical URLs and overlapping commercial pages.

The Most Difficult Part

The hardest part of AllCloneScript was not one technical SEO issue. It was managing:

Two Websites With Almost the Same Product Inventory at the Same Time

Every new product created an additional decision. I could not only ask: What keyword should this product target? I also had to ask: Has Bitrix Theme already claimed that search opportunity? Should AllCloneScript use a secondary variation? Should this product be positioned as a web template rather than website template? Should the UI product emphasize UI design instead of UI kit? Can this keyword belong legitimately to both domains? How do I make both pages useful without making them SEO copies? That required thinking above the individual-page level. The real unit of strategy became:

The Two-Domain Search Ecosystem

not simply:

One Product Page

This is what made AllCloneScript fundamentally different from Bitrix Theme.

What I Learned

AllCloneScript reinforced a lesson that became increasingly important while managing both marketplaces:

Keyword research is also about deciding what not to target.

The obvious highest-volume keyword is not automatically the best choice for every page. And when two websites sell almost the same products, blindly chasing the same commercial terms can create unnecessary internal competition across domains. The project taught me to think about: Keyword Ownership Search Intent Page Differentiation Domain Positioning Content Differentiation together. It also reinforced that two businesses can sell nearly identical underlying products while still developing different search identities if their:

  • Keywords
  • Page angles
  • Content
  • internal links
  • Landing pages
  • Informational strategies

are deliberately separated.

My Biggest Takeaway

From June 2024 to November 2025, I built and executed the SEO strategy for AllCloneScript as its main SEO owner while simultaneously managing Bitrix Theme. The biggest challenge was that both websites sold almost the same underlying digital products. Instead of copying the existing Bitrix Theme strategy, I created a separate search ecosystem for AllCloneScript through: Different Keywords Different Product Titles Different Product Content Different Blog Topics Clone-Script Landing Pages Different Internal-Linking Emphasis Separate Search Positioning At the same time, I managed the website's broader: Product SEO → Content Strategy → Technical SEO → Indexing → Schema → Performance → Internal Linking → Initial Off-Page SEO → Monitoring I no longer have access to the project's historical GSC or GA4 data, so I intentionally do not attach unverified traffic-growth percentages to this case study. The strongest evidence of the work is the strategic problem itself and the system used to solve it: Building a separate search identity for a second marketplace without turning two websites with almost identical product inventories into SEO copies of each other. For me, this project demonstrates that I can: Manage SEO across overlapping domains, decide which search opportunities should belong to which property, differentiate similar commercial pages, coordinate product and content execution, and build a distinct search ecosystem even when the underlying product catalog is almost identical.
